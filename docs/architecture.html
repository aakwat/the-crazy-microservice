Support ticket PoC: layers, flows and responsibilities

Read top to bottom: what lives in each layer, how a request and its events move through them, and how each service is layered inside.

2 · Flows

Numbered steps. Events carry IDs and status only, never ticket text, so personal data stays in the tickets database.

sync HTTPresponse / pushevent via Redis Streams
StreamProducerConsumers
tickets.eventstickets, via outboxrealtime, ai, image

jobs.commandsjobstickets
  • Envelope: {id: uuidv7, type, version, occurred_at, subject_id, traceparent, payload}; payload holds IDs, status, requester_id, assignee_id.
  • Delivery is at-least-once: every consumer dedupes on id. Stuck messages are reclaimed with XAUTOCLAIM; after 5 tries they move to <stream>.dlq.
  • Workers use consumer groups. Realtime does not: each replica reads every event and pushes only to the requester and assignee.

3 · Inside each service

Same four layers everywhere, named the way each language names them. Dependencies point at the domain; the domain imports no framework, database or transport code.

gateway Go

  1. transportmiddleware: recover → trace → limit → authn
  2. approute: path → upstream table
  3. domain(no domain: stateless)
  4. adaptersproxy: httputil.ReverseProxy, JWKS client

auth Java

  1. transportweb/: controllers, DTOs, @Valid
  2. appservice/: register, @Transactional · authserver/: SAS chain, token claims
  3. domaindomain/: User, password policy
  4. adaptersrepository/: MyBatis mappers · keys: signing key

tickets Rust

  1. transporthttp/: axum handlers · consume/: stream consumers
  2. appapp/: create, comment, attach, apply triage
  3. domaindomain/: Ticket, status machine, triage allow-list
  4. adaptersstore/: sqlx · outbox/: relay · blob/: MinIO

realtime Node

  1. transportws/: upgrade, JWT verify, heartbeat
  2. appapp/: route event → sockets
  3. domainregistry: userId → sockets (in memory)
  4. adaptersstream/: XREAD tickets.events

image Go

  1. transportconsume/: attachment.uploaded
  2. appapp/: process one attachment, idempotent
  3. domainthumb/: size check + resize (pure)
  4. adaptersblob/: MinIO · publish/: XADD

ai Python

  1. transportconsumer: ticket.created
  2. appapp: triage one ticket, idempotent
  3. domaindomain: category enum, priority 1–4
  4. adaptersclients: tickets /internal, Ollama, XADD

jobs Python

  1. transportscheduler: timer
  2. appapp: escalate overdue, auto-close stale
  3. domaindomain: SLA rules per priority
  4. adaptersclients: tickets /internal, XADD
